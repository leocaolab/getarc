# 用测试打自己的代码

taste-check 和 error-check 是读代码，结论里有推理。test-check 把它们变成能跑的测试：打穿了，就是一个能复现的 bug，测试直接留下来当回归测试；打不穿，就是一个用测试证明过的防御。

## 步骤

1. **定范围。**选一个 crate 或模块。把已知、已经在修的问题列给破坏者，免得它重复去打。
2. **派破坏者。**用下面的说明派一个子 agent，把它的工作环境写清楚：
   - 用一个干净的临时工作树（先确认 `git status` 干净，切到 `origin/main`；别的会话可能也在用这台机器的工作树，确认没人占着）；
   - 测试写成新文件，不改任何已有的生产代码和测试，不提交、不推送；
   - 跑完删掉自己加的文件，切回原来的分支；
   - 不上共享的 CI 或合并机器（压测和全路径计数会拖慢别人的队列）。
3. **核实。**主会话对每一条「打穿了」，都打开测试代码和原始输出看一遍：失败确实来自被测代码，不是测试自己写错了。
4. **交结果，接着修。**打穿的测试改写成正式的回归测试，放进修复它的那个 PR；每条都写清触发条件和多常见，按概率乘以后果排序。

## 给破坏者的说明

你的唯一目标是写出能编译、真正跑起来的测试，让被测代码出错。代码风格、命名、注释一概不管。

- **先弄清输入从哪来。**读被测代码和它的调用方，把输入分成两类：外部真能给的（客户端的字节、连接的数量和快慢、断开的时机、配置值、信号的时机），和只有调用方用错才会出现的。优先打外部能触发的。
- **攻击点从这些地方找：**
  - 文档里的承诺（「只要 X 被调用，Y 也一定被调用」「返回时一定会取消」），逐条去违反它；
  - 每一个 `Result` / `Option`、每一处会 panic 的地方（下标、算术、`Instant` 加减）；
  - 没有上限的等待（等 token、join、丢掉 tokio 运行时、`recv` 不带超时）；
  - `Drop` 里会做的事，以及 panic 在 unwind 过程中又碰到了什么（payload 析构时再次 panic、守卫的构造顺序）；
  - 并发：重入、唤醒的同时又注册、共享状态被借用时回调外部代码；
  - 量：大量连接、大量任务、超大配置值、0 和边界值。
- **挂住怎么判定。**用一个外层超时：在另一个线程里等，超过 N 秒就判定为挂住。写明 N 的依据，也就是被测路径里有没有自带的时钟、自带的时钟有多长。能做对照的就做对照，比如放行卡住的那个调用之后，看它是否立刻恢复。其余的测试等事件，不等墙钟。
- **内存安全类的问题**，用 AddressSanitizer 或 Miri 跑已有的路径，确认修复成立。目标是验证自己代码的不变量和修复，不是写利用代码。
- **交回三部分：**
  1. 打穿的：完整的测试代码、`cargo test` 的原始输出（关键部分）、触发条件、多常见（常见、少见、几乎不会）、后果、和已知问题的关系。每条再加一句**在哪一边**：是该处理它的地方没处理，还是在不该处理它的地方处理了（一个事实或决定越过了边界），并说出该处理的那一方是谁。
  2. 没打穿的：每个尝试过的攻击点，以及挡住它的具体类型、结构或检查（file:line），再附上那个跑通的测试的名字。
  3. 怀疑但没能写成测试的：说明缺什么，比如需要搭一个替身，或者需要某种机器。

## 注意

- **只有跑出来的才算。**没有测试、只有推理的，放进「怀疑」那一部分，不算打穿。
- **按概率乘以后果排序。**只有调用方用错才会触发的，标清楚。
- **说明要写成防御性测试。**任务说明里写清楚：目标是验证自己代码的契约和修复。不要写成「构造某种内存破坏的利用代码」；那样的说法会被安全分类器拦下，任务就做不完了。
- **和另外两个 skill 的关系。**taste-check 和 error-check 找出来的推理类问题，可以直接交给破坏者写成测试去验证；破坏者打穿的，再用 error-check 的改法模式去修。

## 例子：一个线程运行时模块

11 个测试，6 个通过、5 个打穿（攻击的是 origin/main，不是修复中的版本）：

- **打穿：**panic 的 payload 在析构时又 panic，越过了 `stop_on_failure`，token 没人取消，`join_all` 永远等（几乎不会，新的）。serve panic 时 blocking 池里正好有一个卡住的调用，unwind 时析构运行时挂死，失败永远不公布（少见，是已知根因的 panic 路径）。`before_serve` 里 panic 时 `after_serve` 不会被调用，违反了「成对」的承诺（几乎不会，新的，原因是守卫在调用之后才构造）。还有一条只有调用方用错才会触发的时长溢出。
- **没打穿：**2 万个连接加停机；唤醒的同时重入、丢掉并新建等待者；连接 panic 之后计数照样归零；超时为 0；停机信号早于线程启动。每一条都有一个跑通的测试，并附上挡住它的那段代码的 file:line。
- 前面的四路审查和错误处理审查都是读代码，打穿的三条里有两条它们都没找到。
