# 编码规则

写代码时遵守下面这些规则。

- 注释默认不写; 只写代码说不出的: 为什么这样做、调用方看不见的副作用与出错条件、类型表达不出的不变量。每条注释是完整的句子, 不写历史。
- 类型名是名词, 说它是什么, 不说它在哪用; 不用 Manager / Helper / Data / Info / Context 这类词。
- 只在某个状态下才有的字段, 放进那个状态的变体里; 总是一起出现的几个可选字段合成一个。
- 同一个事实只存一份; 能算出来的不另存。
- 有不变量的字段私有, 只经返回 `Result` 的构造函数造出来。
- 失败的种类有类型, 不写进字符串; 不吞错 (`let _ =`、`.ok()`、`unwrap_or(默认)`), 库代码不 `unwrap` / `panic`。
- 判断写成纯函数: 输入是数据, 输出是决定; IO、时钟、容器的搬运写在外面, 调用判断。
- 没有外部调用方的不 `pub`; 只转发参数的中间层删掉; trait 只在有两个真实实现时才加。
- 每一行都有代价: 删掉一行行为不变, 它就不该存在。只解决现在知道要解决的问题。
- 测试按它测的行为命名; 边界两侧各测一次。
