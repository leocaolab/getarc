# 编程的元则

动手之前, 按下面这几条想清楚这个程序; 写的时候让代码直接是这几条的样子。

1. **程序是变换。** 函数把输入变成输出, 程序是这些变换的组合。会随时间变化的东西是一个状态机: `step : 状态 × 事件 → 状态 × 效应`, 运行就是在事件序列上的折叠。
2. **类型是集合。** 一个类型就是它所有合法值的集合: 和类型是"几种之一", 积类型是"同时都有"。设计类型, 就是让非法的值不在集合里, 让每个合法状态只有一种写法。
3. **数据决定程序。** 先选数据结构; 数据对了, 算法是显然的。算法需要补丁才对, 回去改数据。
4. **一个模块藏一个决定。** 模块的边界划在一个可能变化的决定周围; 别的模块只拿到这个决定的结果, 不知道它怎么做出的。说清每个模块知道什么, 也说清它不知道什么。
5. **契约。** 每个函数说清它要求什么 (前置条件)、承诺什么 (后置条件), 每个不变量由谁维持。
6. **组合。** 小的变换拼成大的; 一处对不对只靠它自己的契约, 不靠被谁调用。
