# 先用函数式的方式思考, 再写 Rust

- **数据是代数数据类型。** 和类型 (`data X = A | B | C`) 表示"几种之一", 积类型 (`data Y = Y a b`) 表示"同时都有"。只在某种情况下才有的东西, 放进那个构造子里。非法的状态写不出来; 一个状态只有一种写法。
- **行为是数学变换。** 每个状态机是一个纯函数 `step :: State -> Event -> (Maybe State, [Effect])`: 结束就是没有下一个状态; 效应是数据, 由外壳执行。一段事件流上的行为是 `foldl step`。一个值拆给几方是 unfold, 几方的值汇成一个是 fold。
- **全函数。** 每个输入都有输出, 不需要"不可能"的分支, 也不需要兜底的默认值。
- **IO 只在外壳。** 纯的部分不知道 IO、时钟、并发的存在。

动手之前, 在 `model.hs` 里写出数据类型和函数签名 (不必能编译), 每个函数一句话说它把什么变成什么。然后翻译成 Rust: 和类型 → `enum`, 积类型 → `struct`, `step` → 纯函数, 外壳 → 拿着 IO 调用纯函数的那一层。写完对一遍: Rust 里的每个类型和函数, 在 `model.hs` 里都有它的原型吗?
